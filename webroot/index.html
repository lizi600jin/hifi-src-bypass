一键预设

点一下即完成「设置 + 应用 + 重启音频服务」，不用逐个调下面的参数。
「自动识别」会读小尾巴对内上报的最高采样率与位深，自动挑一个不超过它、且本模块支持的档位 —— 换耳机/换小尾巴后点一下就行。

直通设置

系统混音器的工作频率。当它与音源一致时，AudioFlinger 会跳过自身重采样 —— 这是让所有 App都免于 SRC 的关键开关。默认档与原厂一致，最稳妥。

USB / 有线的 DIRECT 直通通道的最高采样率。按解码芯片的真实上限设置，不要盲目拉满。
· CX31993 上限 384 kHz / 32-bit，配 MAX97220 耳放。
· 96 kHz / 24-bit：多数 96k 上限的数字小尾巴请选这一档。
· 它真正的短板是位深：原厂通常只给 16bit，本模块补上 24/32bit 才是收益所在。

USB / 有线输出端口允许的位深上限。16bit 永远保留作基线，所以这是"上限"而不是"唯一"：
· 16-bit = 只留 16bit（最保守，排查用）。
· 24-bit = 16 + 24bit。96k 上限的数字小尾巴选这一档。
· 32-bit = 16 + 24 + 32bit，最宽松，默认。
设为高于解码器能力的位深可能导致无声。

关闭则改动在下次重启手机后生效，更稳妥。

一键还原

无损 · 可逆
  • 点「一键还原」＝立刻卸载绑定挂载，回到原厂音频策略，并重启音频服务。当前播放会中断，属正常现象。
  • 还原是无损的：模块从不写入系统分区，原厂音频策略 XML 始终原封不动，只是上面盖了一层临时文件。
  • 还原后模块仍然装着但处于停用状态，你设过的参数会保留，再点一次「应用并生效」就回到原来的配置。
  • 想彻底清除：在 KernelSU / Magisk / APatch 里卸载本模块。卸载脚本会自动卸载挂载、清理 /data/adb/hifi_src_bypass 的全部残留并还原原厂策略。

深度校验（四层证据）

—

跑一次 hifi doctor，把「到底有没有真正生效」拆成四层证据：
A 配置层 生效文件里端口的上限与位深 → B 系统层 audioserver 读到的内容 → C 能力层 解码器声明支持什么（不代表在跑）→ D 链路层 此刻真正协商出的 rate / format 与占用进程。
D 层显示 closed 有三种完全不同的含义，会自动判定是哪一种：
· D1 找到 0 个 pcm 目录 = 本机内核没导出这棵树（不是模块没生效，改检测也没用，以 5b/5c 为准）；
· D2 有目录但全 closed = 检测时暂停了，或播放器正用自带 USB 驱动独占；
· D3 有打开的流 = 出明细。
5c 段会直接点名网易云 / QQ音乐 / 海贝此刻走的是直通、混音路径还是没走音频栈。

原理与边界

  • 只替换本机原厂音频策略 XML（如 /odm/etc/audio/... 或 /vendor/etc/...），用 systemless 绑定挂载，不写入任何分区，卸载即恢复。
  • 以本机原厂配置文件为唯一基线重建，只改采样率与位深，不增删任何混音端口 / 设备端口 / 路由；麦克风、蓝牙、扬声器、空间音频、硬件 FLAC 解码全部保持原样。
  • 本模块把 USB / 有线的 DIRECT 直通端口上限提到你选的档位，并补齐 16 / 24 / 32-bit 三种位深 —— 网易云音乐的「独占 USB 输出」、Apple Music、QQ 音乐 Hi-Res、海贝、UAPP 等走的都是这条 DIRECT 通道。
  • 位深通常才是真瓶颈，不是采样率：原厂 USB 端口的采样率往往本就够用，却只给 16bit。所以本模块对只到 96k 的设备的收益就是「补上 24bit」。位深上限按解码器实际能力选，选高了会无声。
  • 「全局 384 kHz」在 Android 上不存在：系统混音路径必然有固定工作频率。本模块提供的是两条正交的能力 —— ① App 主动申请的独占/DIRECT 直通可达高采样率；② 把全局混音率对齐曲库以消除所有 App 的重采样。
  • 硬件 FLAC / APE 硬解通道（compress_offload_out）按原厂保留，未做提升：这些解码器本身有频率上限，强行提高会导致无声。
  • 若出现无声：点「一键还原」，或卸载模块后重启。
