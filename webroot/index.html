一键预设

点一下即完成「设置 + 应用 + 重启音频服务」，不用逐个调下面的参数。
「自动识别」会读小尾巴对内上报的最高采样率与位深，自动挑一个不超过它、且本模块支持的档位 —— 换耳机/换小尾巴后点一下就行。

直通设置

系统混音器工作频率：与音源一致时 AudioFlinger 不再重采样，让所有 App免于 SRC。
怎么选：按曲库多数采样率 —— 44.1k 选 44.1 kHz（推荐），48k 为主保持 48 kHz（原厂）；192 / 384 kHz 属升采样试听（实验）。

换档把整个混音端口重写成你选的频率（框架取列表最大值，只加一项没用）；免 SRC 的前提是混音率 = 音源率。
改完点「应用并生效」立即生效。

USB / 有线 DIRECT 直通通道允许的最高采样率，够高才能让独占输出的音源不被压到低率。
怎么选：按小尾巴上报的真实上限选（上面「USB 解码器」一格可见）—— 384 kHz 是 CX31993 一类芯片的上限；只到 96 kHz 的选 96 kHz，别盲目拉满。

插上小尾巴后 USB 音频不走混音器，走厂商 HiFi 端口（如 hifi_playback）。
怎么选：钉在你正在听的音源采样率上，该率即比特完美 —— 网易云「超清母带」/ QQ 音乐「臻品音质」多为 192 kHz（推荐），96k 母带选 96 kHz。
其余率只会上采样、不丢内容，永远不要往下选（有损下采样）；auto＝原厂行为。

USB / 有线输出端口的位深上限：原厂常只给 16bit，补齐到 24 / 32bit 后 Hi-Res 音源才不被截位（16bit 始终保留）。
怎么选：解码器能收 24bit 就选 24-bit（推荐），确定支持 32bit 才选 32-bit；16-bit＝最保守基线（实验）。
选高于解码器能力可能无声。

手机扬声器 / 听筒端口的采样率：钉死为曲库采样率后，扬声器回放也免于 SRC（原厂常锁 48 kHz，播 44.1k 会先被重采样）。
怎么选：44.1k 曲库选 44.1 kHz（推荐，配「扬声器一键优化」），其他情况保留 auto＝原厂；不要往下选（有损下采样）。

扬声器 / 听筒端口的位深上限：内置 DAC 多有 24bit 能力，原厂策略却常只声明 16bit，补到 24-bit（推荐） 可减少播放截位损耗。
确定硬件支持 32bit 才选 32-bit；16-bit＝保持原厂。选高于硬件能力可能扬声器无声。

把高通 QTI 的 ADSP ASM 流强制到指定位宽（注入属性 persist.vendor.audio_hal.dsp_bit_width_enforce_mode），让扬声器回放的混音链路以更高位宽工作、减少中间截位。
怎么选：24-bit（推荐），硬件与 ROM 支持时可用 32-bit；16（关）＝原厂行为，出问题第一个回退到它。
点「应用并生效」时注入、重启服务后生效，「一键还原」自动清除（纯属性层）。

一键把扬声器 / 听筒设成「44.1 kHz + 24bit」免 SRC 组合：回放不再被系统重采样、位深同时补齐（推荐）。
「还原 auto (16bit)」把档位交回系统；更高档（192 kHz / 32bit）属 实验，终端跑 hifi speaker hires。

声明 Android 14+ 的 BIT_PERFECT 输出通道（hifi_output）并接入播放路由：播放器用 preferred mixer attributes API 请求即免混音、免重采样，直出比特完美。
需同时满足两项：Android 14+（SDK 34+）与 AIDL 方言；HIDL 老机型、移植 ROM 即使版本新也不支持，取不到版本号时同样按不满足处理。
不满足时开启没有任何损失：应用时被拒绝，不写文件、不挂载、不会卡开机、不会死机重启，本机其余档位照常生效。
怎么选：关闭＝原厂；想验证就开启，再到播放器侧主动请求（实验，未请求走原混音路径，无副作用）。

开启＝点「应用并生效」后自动重启音频服务，改动立即生效（当前播放短暂中断）；关闭＝等下次重启手机生效（更稳妥）。

一键还原

无损 · 可逆
  • 点「一键还原」＝立刻卸载绑定挂载，回到原厂音频策略，并重启音频服务。当前播放会中断，属正常现象。
  • 还原是无损的：模块从不写入系统分区，原厂音频策略 XML 始终原封不动，只是上面盖了一层临时文件。
  • 还原后模块仍然装着但处于停用状态，你设过的参数会保留，再点一次「应用并生效」就回到原来的配置。
  • 想彻底清除：在 KernelSU / Magisk / APatch 里卸载本模块。卸载脚本会自动卸载挂载、清理 /data/adb/hifi_src_bypass 的全部残留并还原原厂策略。

深度校验（四层证据）

—

档位设了却不生效？先跑这里。它一次 hifi doctor（只跑 [1]–[7]），把「到底有没有真正生效」拆成四层证据：
A 配置层 生效文件里端口的上限与位深 → B 系统层 audioserver 读到的内容 → C 能力层 解码器声明支持什么（不代表在跑）→ D 链路层 此刻真正协商出的 rate / format 与占用进程。
D 层显示 closed 有三种完全不同的含义，会自动判定是哪一种：
· D1 找到 0 个 pcm 目录 = 本机内核没导出这棵树（不是模块没生效，改检测也没用，以 5b/5c 为准）；
· D2 有目录但全 closed = 检测时暂停了，或播放器正用自带 USB 驱动独占；
· D3 有打开的流 = 出明细。
5c 段会直接点名网易云 / QQ音乐 / 海贝此刻走的是直通、混音路径还是没走音频栈。
末尾 [7] 就是当前实际输出状态速览，一屏可见。换机型 / 刷入无效要发给维护者的那一段（原 [8]）已移到下面的「机型适配校验」。

机型适配校验

—

这一块解决什么：当你换了机型、或刷入后完全无效时，需要把「本机的病历」发给维护者。 它和上面的深度校验是独立的，所以深度校验窗口一打开就是实时输出状态，不用再往下翻找。
跑的是 hifi adapt（等于 HIFI_PROBE_SECTION=adapt hifi doctor），只做检测、不改任何东西，回答三件事：
① 这台机器到底有哪些策略文件，模块为什么补了它 / 跳过了它（含上次扫描的逐条结论）→ ② 策略基线是什么（模块挂载的东西是从哪份原厂件生成的）→ ③ 音频输出在系统里的真实路径（Config source 指向哪份文件、逻辑端口名、内核设备节点与声卡号）。
反馈时请把这一整段连同上面深度校验的「排查明细」一起发回来，再补一句：型号 / 系统版本 / 小尾巴型号 / 具体现象。

原理与边界

  • 只替换本机原厂音频策略 XML（如 /odm/etc/audio/... 或 /vendor/etc/...），用 systemless 绑定挂载，不写入任何分区，卸载即恢复。
  • 以本机原厂配置文件为唯一基线重建，只改采样率与位深，不增删任何混音端口 / 设备端口 / 路由；麦克风、蓝牙、扬声器、空间音频、硬件 FLAC 解码全部保持原样。
  • 本模块把 USB / 有线的 DIRECT 直通端口上限提到你选的档位，并补齐 16 / 24 / 32-bit 三种位深 —— 网易云音乐的「独占 USB 输出」、Apple Music、QQ 音乐 Hi-Res、海贝、UAPP 等走的都是这条 DIRECT 通道。
  • 位深通常才是真瓶颈，不是采样率：原厂 USB 端口的采样率往往本就够用，却只给 16bit。所以本模块对只到 96k 的设备的收益就是「补上 24bit」。位深上限按解码器实际能力选，选高了会无声。
  • 「全局 384 kHz」在 Android 上不存在：系统混音路径必然有固定工作频率。本模块提供的是两条正交的能力 —— ① App 主动申请的独占/DIRECT 直通可达高采样率；② 把全局混音率对齐曲库以消除所有 App 的重采样。
  • 硬件 FLAC / APE 硬解通道（compress_offload_out）按原厂保留，未做提升：这些解码器本身有频率上限，强行提高会导致无声。
  • 若出现无声：点「一键还原」，或卸载模块后重启。
